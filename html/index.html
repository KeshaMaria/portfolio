Инструкция: как проверить бизнес-данные через CleanBusiness API

Инструкция создана для вымышленного API. CleanBusiness API не существует в реальности. Скриншоты и ссылка в разделе «Получение API-ключа» являются вымышленными. Способы связи в разделе «Обращение в службу поддержки» также являются вымышленными.
На кого рассчитан данный документ: документ рассчитан на разработчика, который понимает, что такое JSON, и умеет составлять JSON-запросы.

Клиенты компании предоставляют свои персональные данные, необходимые для бизнеса. Иногда клиент может допустить ошибку в своих данных. Например, неправильно записать номер телефона. В таком случае менеджер не сможет связаться с клиентом.

CleanBusiness API позволяет проверять корректность данных, которые дают клиенты компании.

API поддерживает проверку четырёх типов данных:

  • Email
  • Телефон
  • ИНН
  • Адрес

Проверка данных состоит из нескольких этапов:

  • Получение API-ключа
  • Создание и отправка запроса в Postman
  • Анализ ответа

Получение API-ключа

  1. Перейдите на сайт https://cleanbusiness.ru
  2. Войдите в личный кабинет или зарегистрируйтесь.
  3. Нажмите «Создать API-ключ».
    Рисунок 1. Кнопка «Создать API-ключ»
  4. Нажмите на «Копировать».
    Рисунок 2. Копирование API-ключа

Создание и отправка запроса в Postman

  1. Перейдите на сайт https://www.postman.com/
  2. Нажмите на «Workspaces» и выберите рабочее пространство (workspace) с вашим именем.
    Примечание: рабочее пространство с вашим именем создаётся автоматически после регистрации в Postman.
    Рисунок 3. Выбор рабочего пространства
  3. Нажмите на иконку «+» и выберите «HTTP».
    Рисунок 4. Создание HTTP-запроса
  4. Заполните поля:
    • Выберите метод POST.
      Выберите метод POST, потому что данные отправляются в теле запроса, а не в URL.
    • Скопируйте https://api.cleanbusiness.ru/v1/validate и вставьте в поле URL
    Рисунок 5. Выбор метода POST и ввод URL
  5. Перейдите на вкладку «Headers».
    Рисунок 6. Вкладка Headers
  6. Добавьте две строки:
    • Key: X-API-Key, Value: ваш скопированный ключ.
    • Key: Content-Type, Value: application/json
    Рисунок 7. Заполнение заголовков
  7. Перейдите на вкладку «Body».
    Рисунок 8. Вкладка Body
  8. Проверьте, что выбрано «raw» и «JSON».
    Рисунок 9. Выбор raw и JSON
  9. Вставьте запрос в формате JSON в текстовое поле.
    Рисунок 10. Вставка JSON-запроса
  10. Нажмите на кнопку «Send» для отправки запроса. После отправки ответ отобразится в блоке «Response».
    Рисунок 11. Отправка запроса и получение ответа

Анализ ответа

Результат проверки данных отобразится в объекте «results».

{
  "results": {
    "email": {
      "input": "ivanov@gmial.com",
      "valid": true,
      "corrected": "ivanov@gmail.com",
      "details": {
        "format_ok": true,
        "mx_exists": true,
        "autocorrect_applied": true
      }
    }
  },
  "request_id": "req_email_123"
}

Успешная проверка данных

Если данные прошли проверку, в поле «valid» отобразится «true».

{
  "results": {
    "phone": {
      "input": "8(495)123-45-67",
      "valid": true,
      "normalized": "+74951234567",
      "details": {
        "format_ok": true,
        "country": "RU",
        "operator": "МТС"
      }
    }
  },
  "request_id": "req_abc123"
}

Ошибка при проверке данных

Если данные не прошли проверку, в ответе отобразится:

  • В поле «valid» отобразится «false».
  • В поле «code» отобразится код ошибки.
  • В поле «message» отобразится причина ошибки.
{
  "results": {
    "inn": {
      "input": "1234567890",
      "valid": false,
      "error": {
        "code": "INN_NOT_FOUND",
        "message": "ИНН не найден в базе ФНС"
      }
    }
  },
  "request_id": "req_ghi789"
}

Справка по ошибкам запросов (HTTP-статусы)

Ответ может поступить без объекта «results» и с числом в поле «code».

В таком случае ошибка возникла не из-за некорректных данных (например, неверного email или ИНН), а из-за того, что сам HTTP-запрос был составлен неправильно.

Например, отсутствует обязательное поле, неверный формат JSON, не передан API-ключ и т.д.

{
  "error": {
    "code": 401,
    "message": "Invalid or missing API key"
  }
}

Таблица: как отличить ошибку данных от ошибки запроса

ПризнакОшибка в данных (валидация)Ошибка в HTTP-запросе
Наличие «results»ЕстьНет
Поле «valid»Есть («true» — данные корректны, «false» — ошибка)Нет
Поле codeТекстовый код (например, INVALID_FORMAT, INN_NOT_FOUND)Числовой код (например, 400, 401, 500)
Что означаетДанные проверены, но некорректныСам запрос составлен неправильно (не передан ключ, неверный JSON и т.д.)
Пример ответа{"results": {"email": {"valid": false, "error": {"code": "INVALID_FORMAT"}}}}{"error": {"code": 401, "message": "Invalid or missing API key"}}

Обращение в службу поддержки

Если вы столкнулись с ошибкой, которая не описана в таблице, или проблема повторяется после повторной попытки, обратитесь в службу поддержки CleanBusiness.

При обращении укажите:

  • Текст запроса, который вы отправляли.
  • Текст ответа с ошибкой.

Способы связи:

  • Email: support@cleanbusiness.ru
  • Чат на сайте: https://cleanbusiness.ru/support (доступен с 10:00 до 19:00 МСК)

Служба поддержки отвечает в течение 24 часов в рабочие дни.
